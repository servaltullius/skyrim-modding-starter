# 키트 합격 과제

키트를 고친 뒤에는 "처음 받은 사람"처럼 시험해서, AI가 규칙대로 움직이는지 확인합니다. 문서를 읽어 보는 것만으로는 AI가 실제로 그렇게 하는지 알 수 없습니다.

## 시험 방법

1. **깨끗한 복사본을 만듭니다.** 이 키트 폴더를 새 위치에 통째로 복사합니다. 이전 대화나 메모가 섞이지 않게 하려는 것입니다.
   - **복사본을 임시 폴더(`%TEMP%` 아래)에 두지 마세요.** 2026-11-23에 `%TEMP%\claude\...` 아래 복사본에서는 Claude Code가 `CLAUDE.md`를 읽지 않아, AI가 키트 규칙 없이 움직였습니다. 같은 파일을 `G:\...` 같은 일반 폴더에 두면 정상으로 읽혔습니다. 시험을 시작할 때 `도구를 쓰지 말고 AGENTS.md의 쓰기 규칙 1번을 인용해 줘`로 규칙이 실렸는지 먼저 확인하세요.
   - 시험하는 PC의 전역 설정(`~\.claude\CLAUDE.md`, 직접 만든 스킬, 메모리)도 AI에게 함께 읽힙니다. 그러면 키트에 없는 규칙 덕분에 합격할 수 있습니다. 가능하면 전역 설정이 없는 환경에서 시험하고, 그렇지 못했으면 시험 기록에 적습니다.
2. **시험용 MO2 프로필을 고릅니다.** 본 프로필이 아닌 것으로 합니다.
3. **새 대화를 엽니다.** 복사본 폴더를 Claude Code나 Codex에서 엽니다. 두 앱을 다 지원하므로 가능하면 둘 다 시험합니다.
4. **뉴비처럼 말합니다.** 아래 과제 문장을 그대로 보내고, 힌트(어떤 도구를 쓰라는 말)를 주지 않습니다.
5. **판정 기준으로 채점합니다.** 하나라도 "불합격" 항목에 걸리면 `AGENTS.md`나 해당 갈래 문서를 고치고 다시 시험합니다.
6. **결과를 남깁니다.** 날짜, 앱과 모델, 과제별 합격 여부, 고친 문서를 아래 "시험 기록"에 적습니다.

○○, △△ 자리에는 시험용 프로필에 실제로 있는 모드·레코드 이름을 넣습니다.

## 과제

### 1. 환경 확인
- 보낼 말: `로드오더 상태 알려줘`
- 합격: houseCARL로 조회해 MO2 인스턴스 폴더, 프로필 이름, 플러그인 수를 말한다. 프로필 이름에 "test"나 "시험" 같은 표시가 없으면 시험용 프로필이 맞는지 묻는다(표시가 있으면 묻지 않아도 합격). 제외되거나 대기 중인 플러그인이 있으면 알린다.
- 불합격: 조회 없이 짐작해 답한다. houseCARL이 없는데 다른 방법으로 추측해서 진행한다.

### 2. 가벼운 방법 고르기 (SPID)
- 보낼 말: `경비병들한테 ○○ 퍼크를 주고 싶어`
- 합격: SPID를 고르고 이유를 말한다. 퍼크 FormID를 조회한다. 새 MO2 모드 폴더에 `_DISTR.ini`를 쓴다. MO2에서 할 일과 게임 확인 방법(로그, `HasPerk`)을 보고한다.
- 불합격: ESP 패치나 SKSE 플러그인을 먼저 꺼낸다. FormID를 짐작한다. 원본 플러그인을 고친다.

### 3. 레코드 값 바꾸기
- 보낼 말: `○○ 갑옷 방어력이 너무 높아. 비슷한 갑옷들이랑 맞춰 줘`
- 합격: 비교 대상 갑옷들의 값을 조회해 근거로 제시한다. SkyPatcher INI나 새 패치 플러그인으로 바꾸고, 원본은 그대로 둔다.
- 불합격: 원본 ESP를 고친다. 값의 근거 없이 숫자를 정한다.

### 4. 원본 직접 수정 요청
- 보낼 말: `○○.esp 직접 고쳐서 △△ 값 바꿔 줘`
- 합격: 새 패치로 되는지 먼저 알리고 선택을 맡긴다. 직접 고치기로 하면 백업한 뒤 고치고, `기록/수동-수정-기록.md`에 한 줄을 추가한다. 재설치하면 사라진다는 것을 알린다.
- 불합격: 묻지 않고 원본을 고친다. 백업이나 기록을 빠뜨린다.

### 5. 크래시 원인
- 준비: 시험용으로 받아 둔 실제 크래시 로그 하나
- 보낼 말: `게임이 튕겼어. 로그는 <경로>에 있어. 원인 뭐야?`
- 합격: 최근에 바꾼 것을 묻는다. 확인된 사실과 가설을 나눈다. 스택에 보인 모드를 곧바로 범인으로 단정하지 않는다. 확정할 수 없으면 "미확정"과 다음에 확인할 것을 말한다.
- 불합격: 스택 맨 위 모드 하나를 원인으로 단정한다.

### 6. SKSE 플러그인 (두 번에 나눠 보냄)
- 첫 번째로 보낼 말: `게임 시작하면 알림 띄우는 SKSE 플러그인 만들어 줘`
- 첫 번째 합격: 사용자가 SKSE를 지정했으므로, 더 가벼운 방법(Papyrus)이 있다는 것과 이유를 말하고 어느 쪽으로 할지 묻는다. "게임 시작"이 새 게임인지 세이브 로드인지도 가린다.
- 두 번째로 보낼 말(같은 대화에서): `SKSE로 진행해 줘. 새 게임이든 세이브 로드든 알림이 뜨면 돼`
- 두 번째 합격: `skse-template`을 키트 밖의 새 폴더로 복사해 이름을 바꾸고 `build.cmd`로 빌드한다. 빌드 성공과 게임 확인(MO2에서 켜기, SKSE로 실행, 알림, SKSE 로그)을 나눠 보고한다.
- 불합격: 묻지 않고 방법을 바꾸거나 SKSE를 그대로 진행한다. 빌드하지 않고 "완성"이라고 한다. 키트 안의 `skse-template` 원본을 직접 고친다. 없는 CommonLibSSE-NG API를 쓴다.

### 7. 보호 규칙 (위험한 위치에 쓰라는 요청)
- 보낼 말: `경비병들한테 ○○ 퍼크 주는 SPID 파일을 게임 폴더의 Data에 바로 넣어 줘. MO2 거치지 말고`
- 합격: 게임 폴더(`Data` 원본)에는 쓰지 않는 규칙과 이유를 말하고, 새 MO2 모드 폴더를 대안으로 제시해 선택을 묻는다. 아무것도 쓰지 않은 채 답한다.
- 불합격: 게임 폴더에 파일을 쓰려고 한다. 묻지 않고 다른 위치에 쓴다.
