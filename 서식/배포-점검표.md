# 배포 전 점검표

만든 모드나 패치를 넥서스 등에 올리기 전에 확인합니다. AI에게 `배포 점검표대로 확인해 줘`라고 하면 항목별로 확인하고 결과를 보고합니다. AI가 확인할 수 없는 항목은 "사용자 확인 필요"로 표시합니다.

## 권한

- [ ] 다른 사람 모드를 고친 패치라면, 원작자의 허락 조건을 확인했다. 넥서스 모드 페이지의 Permissions 항목을 봅니다.
- [ ] 다른 사람의 에셋(메시, 텍스처, 애니메이션, 스크립트, 플러그인 원본)이 압축 파일에 들어 있지 않다. 허락받은 경우는 출처와 허락 내용을 설명에 적었다.
- [ ] AI로 만든 결과물에 대한 배포처의 규정(고지 의무 등)을 확인했다. 규정은 배포처마다 다르고 바뀔 수 있으니 직접 확인합니다.
- [ ] SKSE 플러그인이라면, DLL에 함께 들어간 라이브러리(CommonLibSSE-NG, spdlog, fmt 등)의 라이선스 고지를 넣었다. `skse-template`의 배포용 zip은 `<플러그인 이름>-licenses` 폴더에 이 고지를 자동으로 넣습니다. 각 라이브러리의 라이선스 조건은 사용자가 확인합니다.

## 내용

- [ ] 압축 파일 구조가 `Data` 기준이다. 예: `SKSE\Plugins\내모드.dll`, `내모드.esp`, `Scripts\내스크립트.pex`
- [ ] 패치 플러그인의 마스터 목록이 설명에 적은 요구 모드와 일치한다(houseCARL로 확인).
- [ ] houseCARL `housecarl_check`에서 이 모드가 새로 만든 오류가 없다. 오류 총수가 아니라 작업 전후의 오류 항목을 비교했다.
- [ ] 생성 도구 결과물(PGPatcher, DynDOLOD, Synthesis 등)을 포함하지 않았다.
- [ ] 버전 번호를 올렸고, 바뀐 점을 적었다.

## 시험

- [ ] 이 모드와 요구 모드만 켠 **깨끗한 프로필**에서 새 게임으로 시험했다.
- [ ] 기존 세이브에 넣었을 때와 뺐을 때 어떻게 되는지 확인했거나, "새 게임 권장" 같은 안내를 적었다.
- [ ] SKSE 플러그인이라면, 시험한 게임 버전(예: AE 1.6.1170)을 설명에 적었다. 시험하지 않은 버전은 "미확인"으로 적었다.

## 설명 페이지

- [ ] 요구 모드: SKSE, Address Library(SKSE 플러그인일 때), SPID·KID·SkyPatcher(INI일 때), 마스터 플러그인
- [ ] SKSE 플러그인이라면 Microsoft Visual C++ 재배포 가능 패키지(x64, 2015~2022 이후판)가 필요하다고 적었다. `skse-template`은 이 런타임을 쓰도록 빌드됩니다.
- [ ] 지원 게임 버전과 시험한 버전
- [ ] 설치 방법, 제거 방법(제거해도 세이브가 괜찮은지)
- [ ] 알려진 문제

## 개인 정보

- [ ] 압축 파일, 로그 예시, 스크린샷에 Windows 사용자 이름이 든 경로(`C:\Users\<이름>`)나 이메일이 없다.
- [ ] **올릴 zip 속의** SKSE 플러그인 DLL에 사용자 이름이나 빌드 경로가 박혀 있지 않다. `skse-template`은 `/d1trimfile`로 소스·라이브러리 경로를 지우지만, 새로 추가한 라이브러리나 디버그 설정까지 보장하지는 않으므로 최종 DLL을 검사합니다(AI에게 "zip 속 DLL에 내 사용자 이름이 있는지 검사해 줘").
- [ ] 키트의 `기록/수동-수정-기록.md`, 원본 백업 파일처럼 내 경로·프로필 이름이 든 파일을 함께 올리지 않았다.
