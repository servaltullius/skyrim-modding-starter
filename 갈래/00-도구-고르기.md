# 도구 고르기

모든 작업은 여기서 시작합니다. **원하는 결과를 내는 가장 가벼운 방법**을 고르세요.
위쪽 방법일수록 만들기 쉽고, 다른 모드와 덜 부딪히고, 망가져도 되돌리기 쉽습니다.

## 하고 싶은 일로 찾기

| 하고 싶은 일 | 방법 | 빌드 필요 | 갈래 문서 |
|---|---|---|---|
| 모드리스트 문제 찾기: 끊긴 참조, 버전이 안 맞는 패치, 어떤 모드가 이기는지 | houseCARL 조회·검사 | 없음 | `01-모드리스트-점검.md` |
| 여러 NPC에게 주문·퍼크·아이템·키워드·의상·팩션 나눠 주기 | **SPID** (`*_DISTR.ini`) | 없음 | `02-INI-배포.md` |
| 아이템·무기·방어구에 키워드 붙이기 | **KID** (`*_KID.ini`) | 없음 | `02-INI-배포.md` |
| 레코드 값 바꾸기: 방어력, 가격, 무게, 이름, NPC 한 명의 속성 | **SkyPatcher** INI | 없음 | `02-INI-배포.md` |
| 두 모드가 같은 레코드를 고쳐서 한쪽이 무시될 때 둘 다 반영하기 | **패치 ESP** (houseCARL로 새 플러그인) | 없음 | `03-ESP-패치.md` |
| 새 아이템·주문·NPC 같은 새 레코드 만들기 | **패치 ESP** | 없음 | `03-ESP-패치.md` |
| 조건(무기, 종족, 키워드 등)에 따라 다른 애니메이션 쓰기 | **OAR** (`config.json`) | 없음 | houseCARL 스킬 `open-animation-replacer` |
| 게임 중 일어나는 일에 반응하기: 퀘스트 진행, 이벤트, MCM 설정 메뉴 | **Papyrus** 스크립트 | 컴파일 | `04-Papyrus.md` |
| 엔진 동작 바꾸기, 성능 개선, 스크립트로 안 되는 새 시스템 | **SKSE** 플러그인(C++) | C++ 빌드 | `05-SKSE.md` |
| 튕김, 멈춤, 무한 로딩의 원인 찾기 | 증거 수집과 가설 가르기 | 없음 | `06-크래시-원인찾기.md` |

## 고를 때 따질 것

1. **INI로 되는가?** SPID, KID, SkyPatcher는 게임이 켜질 때 INI를 읽어 적용합니다(SPID는 각 NPC가 로드될 때 배분). 플러그인 칸을 쓰지 않고, 대상 모드를 업데이트해도 대개 그대로 동작합니다.
   - 이 세 가지는 각각 SKSE 플러그인으로 된 모드입니다. 설치되어 있어야 합니다. AI가 houseCARL로 설치 여부를 확인합니다.
2. **INI로 안 되면 패치 ESP.** 레코드 구조를 바꾸거나 새 레코드를 만들어야 하면 패치 플러그인을 씁니다. 원본은 그대로 두고 새 플러그인에 씁니다.
3. **레코드로 표현이 안 되는 "동작"이면 Papyrus.** 다만 스크립트는 세이브에 흔적을 남깁니다. 플레이 도중에 넣고 빼기 어렵습니다.
4. **Papyrus로 못 하거나 너무 느리면 SKSE.** C++ 빌드 환경이 필요하고, 게임 버전마다 동작이 달라질 수 있어 가장 무겁습니다.

## AI가 지킬 것

- 고른 방법과 이유를 한두 문장으로 먼저 말합니다. 더 가벼운 방법을 두고 무거운 방법을 골랐다면, 가벼운 방법이 왜 안 되는지도 말합니다.
- 사용자가 특정 방법을 지정했어도(예: "SKSE로 만들어 줘") 더 가벼운 방법으로 된다면 그 사실을 알리고 선택을 맡깁니다.
